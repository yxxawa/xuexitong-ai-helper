# 1.0.6 断线恢复与验证记录

日期：2026-10-17。处理“挂了一晚但没有做题”的可复现启动、断线与任务状态问题；没有旧版现场日志，不能据此断言用户此前事件的唯一原因。

| 问题 | 处理后的行为 | 回归 |
| --- | --- | --- |
| 题目页打开早于桥接，之后不自动开始 | 保留自动启动意图，等待连接后启动一次；取消倒计时、暂停、停止均有效 | `web-task.test.cjs` |
| 短暂断线导致原请求删除 | 保留同一个邮箱和随机编号，最长等待恢复 30 分钟后继续原消息 | `web-bridge.test.cjs` |
| 刷新后无法继续原回答或误重发 | 先标记发送中；新实例只按编号重新关联最新用户消息，从不再次提交原题 | `web-bridge.test.cjs`、`deepseek-retry.test.cjs` |
| 刷新丢失会话用量与上一题编号 | 标签页内保存恢复上下文，下一题核对原会话，50 次后正常轮换 | 八小时虚拟时间回归 |
| 断线时任务占用失效 | 保留续租，恢复后核对或由接收端重新授予；不同任务仍互斥 | `web-bridge.test.cjs` |
| 错误后队列接连失败、状态难判断 | 显示等待阶段、秒数和具体原因，请求异常暂停后续题目 | `web-task.test.cjs` |
| 长暂停与断线叠加后误超时 | 暂停和已记账的恢复时间只计算一次 | `web-bridge.test.cjs` |
| 章节测验未等到桥接就退出 | 等待后启动，显示状态并提供暂停、继续和停止 | 共用连接等待与暂停控制；代码检查 |

自动测试 87 项，另执行 TypeScript 检查、正式构建及 userscript 语法检查。八小时虚拟时钟样例完成 80 个模拟请求，各只提交一次，包含两次 5 分钟断线和第 50 次后的会话轮换。

Chrome 正式脚本已验证：题目页先打开会等待，启用专用页后自动开始；限流期间刷新专用页后，原消息按至少 3 秒间隔重试并读回答案，再继续第二题。两题共两条用户消息，原生重试间隔约 3.1 秒，未重复发送。停止等待后再启用新专用页，题目仍未作答且未生成请求邮箱。状态与按钮截图已检查。浏览器样例只使用本地模拟课程与响应，不提交真实课程。历史登录网页的原生 429 验证见 [DeepSeek 网页说明](deepseek-web.md)；本版没有真实整夜账号验证。网页冻结、电脑睡眠、持续登录失效、验证码和网页 DOM 改版仍可能需要人工处理。

更新后需刷新学习通及 DeepSeek 专用页，并在空白专用会话重新点击“启用此标签页”。缺少新版恢复能力的接收端会在发送前提示刷新。

## 确认的问题与更新

| 场景 | 原来的问题 | 1.0.9 处理 |
| --- | --- | --- |
| 慢网、任务列表晚到、iframe 延迟挂载 | 搜索窗口由启动时附件数决定，实际仅 3–10 秒；附件数又被当作轮询次数扣减，容易漏任务并跳走 | 持续读取任务列表，以实际任务 ID 和挂载状态调度；30 秒无变化且仍有必需任务未就绪时暂停并说明原因 |
| 两个任务复用同一个 `mid` | 按 `mid` 去重会把不同任务合并 | 按 `jobid/_jobid` 去重 |
| 多层有声 PPT、坏 iframe 数据 | 只尝试两层 `data`，直接 JSON.parse 和 attachments.find，单个异常会影响整个搜索 | 向上遍历 frame 元数据，容错解析；单个不可读 frame 不阻断可读兄弟任务 |
| 续播已看一半的视频 | 开始播放时强制 `currentTime = 0` | 保留播放器恢复的进度；仅已经结束的媒体重新播放时回到开头 |
| 资源损坏、网络失败 | 本项目播放器的错误检测以正常完成结束，章节调度又吞掉任务异常，可能直接跳章 | 区分完成、失败和取消；错误向上传递，页面显示原因并停止自动跳转 |
| 缓冲卡死、播放器被替换 | 没有可靠的无进展终止条件，可能一直占住当前任务 | 检查原生 media.error、元素存活和播放进度；连续 2 分钟无进展时暂停；手动验证/题目等待不算网络卡死 |
| 浏览器禁止自动播放 | 只匹配某段英文错误，显示弹窗后就返回成功 | 兼容 NotAllowedError；等待用户原生交互后的真实播放结果；取消/离页后旧回调无效 |
| 频繁 pause、学习中调音量/倍速 | 恢复播放可并发，且闭包中的旧倍速可能覆盖用户的新值 | 合并播放请求，恢复时读取当前设置 |
| 末章仍有第二个小节 | 只判断最后一章就结束 | 必须同时位于最后小节；两种自动模式都继续处理剩余小节 |
| 跳转未完成任务点模式 | 非最后小节没有推进分支；末尾没有后续未完成章节时不点击 | 推进小节；查找后方任务并允许回到前方未完成章节；只剩当前章时明确提示而非空转 |
| 随机视频题目与验证弹层 | 删除题目并隐藏所有 .x-component-default，可能误伤验证且并不代表原生提交成功 | 保留原生 UI，同一弹窗只尝试一次随机提交，失败/手动模式等待用户处理 |
| 人脸提示被 CSS 隐藏 | 仅看 src 或内联 display，可能把隐藏的旧元素当作仍需验证 | 按实际可见性判断；仍只通知并等待手动验证，不自动识别或绕过 |
| 计时阅读、PPT 接口还没准备好 | 相对 URL 会抛错，非法 timing 可能使等待立即结束；接口缺失也可能无声结束 | URL 使用页面基址并验证 timing；接口缺失报错；仅提示预计等待结束，不宣称后台完成 |
| 切章/离页时还有异步工作 | 老页面的播放恢复、定时等待、答题及跳转可能继续 | 学习启动单飞，pagehide 中止调度、播放器、手动验证等待、章节答题及跳转倒计时 |

上游 OCS 快照也存在搜索 3–10 秒、附件计数扣减、按 mid 去重、直接解析 frame、播放时进度归零、末章判断以及通用弹层隐藏等相同设计。因此本次不是简单同步上游：共享问题在本项目中单独修正。

# DeepSeek 网页桥接（实验）

## 使用

1. 更新安装构建出的 `xuexitong-ai-helper.common.user.js`，同意脚本新增的 `https://chat.deepseek.com/*` 匹配权限。学习功能仍然只匹配学习通。
2. 学习通面板 → 设置 → **AI 来源：DeepSeek 网页（实验）** → **打开 DeepSeek 专用标签页**。
3. 在该浏览器中登录 DeepSeek，使用空白新对话。可在启用前选择网页上的模型/模式；插件的 API 模型 ID、温度、token 上限和视觉配置不控制网页。
4. 点击专用页右上角的 **启用此标签页**，回学习通开始。不要关闭专用页、在其中手动聊天或切换模型/对话。
5. 不再使用时点击 **停止桥接**。API 来源可随时切回，原 API 配置保留。

普通 DeepSeek 标签页没有学习面板，也不会自动接收题目。只有从专用入口打开并显式启用的页才接收请求；同一会话最多实际发送 50 次，前 49 次不跳转，第 50 次回答完成后新建空白会话并自动恢复接收。命中本地缓存不计次数，面板显示当前会话用量。浏览器需允许该标签页持续运行；标签页被冻结/休眠时可能超时，应改用 API 或保持专用页运行。

**图片：** 支持题干、选项及相邻内容的图片，按原顺序编号后上传；已知有图片但地址不可读、任何图片下载/上传失败、数量不符或网页未允许发送时，不退化为只发文字。原生文件输入框会立即清空，因此适配器会同时检查全部具名缩略图和网页的发送就绪状态。桥接自身限制为每题最多 10 张、单张 10 MB、总计 20 MB，以控制跨页存储开销；超过限制整题报错，不截断附件。网站自身限制仍以网页为准。更新后须刷新旧专用页并重新启用，旧接收端不能接收需要新版任务互斥的请求。

**限制：** 网页模式不报告 token 消耗，不保证免费、无限额度或长期兼容。API 视觉设置不影响网页的原生上传。题目、图片和答案会进入当前网页账号的历史记录；请确认你有权分享这些内容。

## 任务互斥与提示词

- DeepSeek 网页模式固定串行：自动答题（含章节测试）和手动搜题不能同时启动，搜题中其他搜题也不可启动。按钮显示占用状态，快捷键与请求入口也执行同样检查，不能只靠按钮外观限制。
- 唯一接收标签页授予跨标签页/iframe 的任务占用，覆盖整次自动答题，而不是每题结束就放开；暂停和重启等待旧请求期间继续占用，完成/异常后释放，关闭页面或失活的占用会被清理。API 模式保留原并发能力。
- 输出格式统一使用一份内置 JSON 提示词。已移除“AI输出限制”输入框，旧版本残留/导入的自定义提示词不会拼进 API 或网页请求。

## 实现与安全边界

- `packages/scripts/src/utils/web-ai.ts`：同一用户脚本的 GM 存储邮箱。每个请求有随机 ID、目标接收会话和独立 key；一个接收标签页串行消费，避免不同题目相互覆盖。
- `packages/scripts/src/utils/deepseek-web.ts`：DOM 适配器。操作原生文件输入框、文本输入框和发送控件，读取带正确请求 ID 的完整 JSON；还要求回答操作工具栏出现、未识别到生成中控件且文本稳定，防止读取旧对话或半截输出。
- 复用会话时核对专用页路径和上一回答的请求 ID；只读本次请求 ID 对应的完整答案，不借用上一轮回答的完成工具栏。切换到其他聊天会停止接收。
- 每题只有一次发送动作。网页返回畸形答案、离线、限流、超时或页面刷新时不自动重发；接收端出错即暂停，需要人工查看。网页仍在生成的内容不会被强行删除。
- 每个标签页实例还拥有独立连接标识，防止多个接收端或复制标签页同时消费。已有个人聊天、未发送文字和附件不会被覆盖。
- 不读取 Cookie、访问令牌或网页私有状态，不模拟私有接口，不解 PoW、不绕过登录/验证码/风控。
- 图片以临时 base64 附件经同脚本 GM 存储跨页传递，完成/失败时释放请求正文和图片并删除邮箱；浏览器崩溃后过期邮箱会在下次启用接收端时清理。网站自身历史记录需要用户自行管理。API 缓存与网页缓存隔离；网页缓存还按本次启用会话隔离。

网页不是稳定 API。输入框或回答 DOM 改版可能使检测失败，因此遇到“未识别输入框”“未确认发送”“回答超时”时，不应盲目连续重试；先去专用页确认是否已经发送、是否登录或出现验证码。

## 验证范围

- 单元测试覆盖：完整 JSON/请求 ID 校验、不同请求邮箱、过期连接、清理、题干及选项图片顺序、未读全图片零发送、旧接收端能力检查和附件限额。
- `tests/browser-bridge.cjs` 用本地模拟的两张学习通页面和一张 DeepSeek 页面，验证跨域通信、单接收端、串行处理、会话复用、作业题目预先展示、跨标签页互斥、结果展示与手动中断。不会访问账号或产生真实模型费用。
- `tests/web-conversation.test.cjs` 用虚拟时钟验证完整 51 次请求：前 50 次同会话，第 51 次进入新会话，恰好一次切换且无重复发送；`tests/web-activity.test.cjs` 覆盖同时争抢、整任务占用、过期恢复和旧接收端拒绝。
- `tests/browser-deepseek-images.cjs` 模拟原生附件流程，覆盖多图全部就绪、上传失败/缺图不发送、清空 file input 不等于上传完成、禁止重复点击/回车，以及新版回答工具栏。
- **2026-09-20 已进行真实登录网页测试**：临时无持久化浏览器会话，只使用生成的非敏感几何图案；网页能描述图片。随后直接运行本项目适配器，上传图片、仅发送一次选择题，读取到正确答案 `A` 及匹配的请求 ID。没有读取或导出 Cookie/令牌，账号密码未写入代码、配置或文档，测试浏览器已关闭。真实测试验证了页面适配器；学习通到网页的完整跨页链路仍由本地模拟回归覆盖，不代表所有账号/网络/后续网页版本均可用。

## 实测接口流程（2026-09-20）

仅记录接口路径与结构，不记录账号、Cookie、令牌、文件 ID 或对话 ID：

1. 原生文件输入触发 `POST /api/v0/file/upload_file`，以 multipart 上传图片。响应的 `data.biz_data` 包含文件 `id`、`is_image` 和初始 `PENDING` 状态。
2. 网页通过 `GET /api/v0/file/fetch_files` 查询处理结果；本次图片变为 `SUCCESS`，返回图片宽高等元数据。
3. 网页完成自身的会话/请求准备后，调用 `POST /api/v0/chat/completion`，其中 `ref_file_ids` 引用已上传文件，另含 `prompt`、`model_type`、`thinking_enabled`、`search_enabled` 等字段。
4. 页面显示回答；本项目按请求 ID 和完成工具栏读取，不截取思考流。

这些是网页内部接口，不是稳定的公开 API。实际实现交由已登录页面自身完成鉴权、请求校验和流处理，不硬编码令牌、不复制 PoW 算法，也不把 base64 拼成纯文本让模型猜图。

## 扩展到其他 AI 网页

可以扩展，但不是改一个域名就能保证工作。`WebChatAdapter` 将页面相关工作限制为五个方法：

- `assertEmpty()`：验证登录后的空白专用会话，不能覆盖用户聊天；
- `assertReady()`：允许当前已授权会话的历史，但禁止未发送草稿、残留附件或正在生成；
- `submit(prompt, cancelled, images)`：附件全部就绪后只发送一次，区分“未发送”与“无法确认发送”；
- `readCompleted()`：识别最终回答、正确请求 ID、完成状态，排除思考流与旧消息；
- `reset()`：新建独立对话，并保留专用标签页的授权状态。

新增适配器后，还须在来源配置、入口白名单、用户脚本元数据和桥接状态校验中注册对应站点，添加自己的模拟及真实账号测试。默认不匹配 ChatGPT、Claude、Gemini 等其他站点。不得将验证码、登录失败或限流“适配”为自动绕过。

# 程序题与粘贴支持

1.0.7 支持超星的 CodeMirror 程序题（类型 17），用于作业、考试和章节测试的程序编辑器。

当前页面将粘贴标记为 paste，随后在 CodeMirror 的 beforeChange 回调里取消变更并提示“只能录入不能粘贴”。旧版复制粘贴处理只移除了 UEditor 的回调，因此不能解决程序题。

更新完整版脚本后，直接在程序编辑区按 Ctrl+V，或通过右键菜单粘贴。实现从当次原生粘贴事件获取纯文本，使用 CodeMirror 的公开编辑接口替换选区；无需读取系统剪贴板的额外权限。保留缩进、换行、注释、选区替换、撤销及原有其他编辑校验，翻页或延迟创建的编辑器也会启用。

自动答题将当前语言（例如 Python 3.6.9）加入题目，以一个完整的代码字符串读取答案，通过编辑器 API 回填，并同步 backing textarea 与程序题的 JSON 保存字段。编辑器未加载、只读、写入失败或任务取消时不标记完成。已有代码先运行一遍，本次运行通过就跳过，不请求 AI 或重写；没有代码时照常请求 AI。支持答案检验；结果显示保留源码，不把代码中的 # 分割成多空。

安装文件统一为 `dist/xuexitong-ai-helper.user.js`，完整版已包含程序题粘贴功能，不再随生产构建生成独立粘贴助手。覆盖安装后刷新题目页即可使用。

构建命令为 `npm run build`，输出目录只保留这一个安装文件。程序题专项测试为 `node --test tests/programming.test.cjs tests/programming-runner.test.cjs tests/programming-drafts.test.cjs`。

## 1.0.8：无注释默认规则与运行纠错

- 初次生成及运行后的修正请求均要求：除非题目明确要求，否则源代码不写注释。粘贴/解析不会直接删除 # 等字符，防止破坏字符串、预处理指令或题目要求的注释。
- 每次回填后点击本题的原生“运行”，只读取本次新产生的结果；全部 result_right 才认定通过。编译错误、运行异常、测试用例不通过均进入纠错。
- 纠错请求带原题（含当前编程语言及图片）、当前完整代码和完整运行错误，通过原有 AI API 或 DeepSeek 网页来源发送，绕过旧答案缓存。
- 每题最多运行 3 次：初次 1 次，失败后最多 2 次修正并运行。第 3 次仍失败则记录原因、保持未完成状态并继续下一题，不再发送第 3 次纠错请求。
- 已有代码先按原样运行，本次运行通过就直接完成，不请求 AI、不回写原代码；失败才带原题、代码和新报错请求纠正。没有代码时先请求 AI。只缓存本次运行通过的代码，失败后移除本题缓存；页面旧结果、服务不可用和超时不当作通过。
- 暂停期间不点击运行、不发送纠错及回填；停止或手动修改代码会阻止旧结果继续写回。答案检验中接受的程序也必须通过一次运行，才能提交为已接受答案。

浏览器验证采用当前页面的原生运行按钮和结果回调，对运行接口返回作本地模拟，并使用模拟 AI 修正：验证了失败后第 2 次通过、连续失败第 3 次跳过，以及原题/代码/报错完整传递。未调用真实 AI 或提交作业，验证后恢复原有内容。

1.0.8 验证结果：完整回归 116 项通过，含程序题 29 项；TypeScript 编译、完整构建及安装脚本语法检查通过。浏览器证据位于 output/playwright/programming-runner-live-verification.json。


## 1.0.12：先运行已有程序

“开始答题”和“补全未完成”采用以下流程：

1. 没有代码：按正常 AI 作答流程生成、回填并运行。
2. 已有代码：不先请求 AI，不调用编辑器写入接口，直接运行当前完整代码一次。
3. 本次运行通过：保持代码原样，直接跳过 AI 作答和纠错。
4. 本次运行失败：将原题、编程语言、图片、已有代码和新报错发送给 AI 修正，再回填运行；已有代码的首次运行计入最多三次的总限额，因此最多追加两次 AI 纠正。

每次重新开始都会核验当前程序，页面残留的绿色结果或上一次完成标记不替代本次运行。运行按钮未就绪、超时或无法读取新结果时保持未完成，不凭旧结果误判。等待 AI、暂停或运行期间手动修改代码会停止旧回答回填，保留手动内容。

“重新答题”仍是显式重做，会重新请求答案。API 和 DeepSeek 网页来源共用上述控制流程；既有正确代码不占用模型请求。1.0.11 曾改为先让 AI 重写所有已有程序，该行为已在本版取消。

回归使用模拟 AI 与原生运行回调，覆盖正确程序不写回、错误程序先运行再纠正、空白题正常请求、连续三次失败、旧绿色结果与手动编辑保护；未修改真实账号作业。


## 1.0.13：无需改码恢复原生运行

在实际电脑端作业页确认：程序运行完成后，页面把闭包中的 `runSignal` 设为 `true` 并保留灰色按钮；只有编辑器的 `change` 监听器才会重置该状态。仅移除灰色类不能重新运行，旧版直接跳过灰色按钮也会漏掉已有答案。

- 按钮处于运行后灰色状态且已空闲时，通过 CodeMirror 的公开 `signal` API 通知本题原生 `change` 监听器，恢复页面自己的运行状态，然后点击原生运行按钮。
- 不调用 `setValue`、不插入/删除字符、不重写已保存答案；保持代码、选区和撤销历史。未发生真实改码时恢复页面原有的内容变更标记，不额外触发保存。
- 页面仍显示正在运行时先等待结束；等待有超时，支持暂停和取消。本题同时只能有一次插件运行验证，不并发点击。
- 只处理已确认的运行后灰色状态，不解除原生 disabled、aria-disabled、只读或禁用编辑器。控件被替换、语言/代码被手动修改时停止旧任务。
- 仍要求本次新结果才能通过；已有正确代码不请求 AI，只有本次运行失败才进入原有的最多三次运行纠错流程。

验证：程序题相关 68 项、全量 278 项测试及 TypeScript 检查通过。在用户提供的实际页面，对两道已有程序完成原生按钮/编辑器验证，合计拦截模拟 7 次运行响应；涵盖重新运行、等待已有运行结束及并发防重。代码、选区、撤销历史、提交字段和内容变更标记均保持不变。未调用真实 AI、未请求真实运行后台、未提交作业；该浏览器验证不代表判定实际答案正确。
